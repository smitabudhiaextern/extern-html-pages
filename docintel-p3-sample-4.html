Find Every Word and Where It Sits

Pfizer gets thousands of vendor documents, like quality certificates. A compliance team has to flag any that are more than 3 to 4 years old. To find a date, a program first needs every word and where it sits on the page. That's the first layer you'll build today.

Checked against sample-sdf-document.pdf and the walkthrough video · Oct 28, 2026 · [Content owner], Extern + [Pfizer mentor] · Code tested with PyMuPDF 1.26.5

Bounding box: the invisible rectangle around a word on the page. It's four numbers: left, top, right, bottom.

They're coordinates (positions on the page) in points, a tiny unit of 1/72 of an inch, counted from the top-left corner. So (0, 0) is the top-left, and the second number gets bigger as you go down.

Learn: five steps

Here are the five moves a document AI engineer makes on sample-sdf-document.pdf. Each one is a line or two of code.

  1. Install PyMuPDF and import it. PyMuPDF is a library, a ready-made toolbox of code for reading PDFs. It imports as fitz, its old name. pip is Python's installer, and the ! tells Colab (Google's free tool for running Python in your browser) to run it. 
    !pip install pymupdf
import fitz
import json
  2. Open the file and check it has 3 pages. Metadata means facts stored about the file, like its title and author. 
    doc = fitz.open("sample-sdf-document.pdf")
print(f"Total pages: {doc.page_count}")   # Total pages: 3
print(doc.metadata)   # title, author and dates are empty for this file
  3. Read the words on one page. doc[2] is page 3, because Python counts from 0. This works because the file has a text layer: the words are stored as real text, not a picture. 
    page = doc[2]
words = page.get_text("words")
  4. Unpack one word into its box and its text. Each word is a tuple of 8 values, and *_ means "ignore the rest". 
    x0, y0, x1, y1, w, *_ = words[0]   # w is 'Cytiva', x0 is 480.0
  5. Loop through every page, keep each word's page, text and box, and save them as JSON. JSON is a plain text format other programs can read. 
    results = []
for page_num in range(doc.page_count):
    page = doc[page_num]
    for x0, y0, x1, y1, w, *_ in page.get_text("words", sort=True):
        results.append({
            "page": page_num + 1,
            "text": w,
            "bbox": [round(x0), round(y0), round(x1), round(y1)]
        })

with open("sdf_words.json", "w") as f:
    json.dump(results, f, indent=2)

print([r for r in results if r["page"] == 2 and r["text"].startswith("20")])

    The last line keeps only the page-2 entries whose text starts with 20, which is how you spot the two dates.

The engineer's worked example

Here's what the engineer got for the two dates on page 3, straight from sdf_words.json. The label "Date of Manufacture:" comes out as three entries ("Date", "of", "Manufacture:"), so you see only the last one here.

{"page": 3, "text": "Manufacture:", "bbox": [85, 203, 143, 217]}

{"page": 3, "text": "20260315",     "bbox": [200, 239, 244, 253]}

1"page": 3 tells you where the word came from. That matters because pages 2 and 3 both have a Date of Manufacture.

2"bbox" is four numbers: left, top, right, bottom, counted from the top-left corner of the page.

3The label "Manufacture:" and the value "20240315" share the same top and bottom, 203 to 217. So they sit on the same line. The value starts at 200, to the right of the label.

4sort=True put the words in reading order, top to bottom. Without it, page 2 jumps from "Certificate of Quality" straight to the footer, before the dates.

Go deeper

Optional. Open any topic for a guided explanation.

Why "Date of Manufacture:" comes out as three items

The "words" mode splits text wherever there's a space. So one label becomes "Date", "of" and "Manufacture:", each with its own box.

That's expected. In the next step of Project 3, you'll join them back up using regex (a rule that matches a pattern in text) and anchor phrases (fixed labels like "Expiration Date:" that tell you where to look).

What happens to the tables

The "words" mode doesn't know about tables. Each cell's words come out one by one, with their boxes.

PyMuPDF also has page.find_tables(). On this file it finds the test results table on page 3 (7 rows, counting the header). On page 1 it finds no table, even though you can see one. That's one reason the boxes matter: they tell you which words sit on the same row. Ask Chaitanya to review whether to teach find_tables here or leave it for later.
