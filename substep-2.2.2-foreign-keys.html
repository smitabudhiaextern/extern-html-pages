Foreign Keys
Picking up where primary keys left off

Every pizza has its own id now.

Each pizza on the menu has a unique id — its primary key.
Now picture a real order coming in. The system has to record which pizza that order is for. So what should it store — the pizza's name? Its price? Or something simpler and more reliable?
A second sheet enters

Orders store a number, not a name.

Each order stores a pizza_id — not the pizza's name or price.
Why a number instead of "Margherita"? A name can be edited or reused, so it isn't safe to rely on. The id is stable and unique — it never changes and no two pizzas share it. Store that, and the link to the right pizza can never break.
