How a Mod Works

Our example: every new substep should be checked by content-fixer before Smita sees it. Here is how that happens today with a written rule, and how it would happen with a mod.

A mod is a small add-on that sits inside Claude Code and watches for a moment, like "a file was just saved". When that moment comes, the mod does its job automatically, every single time. Claude does not have to remember anything.

Today: a written rule

Like a sticky note on the fridge. It works if someone reads it.

1. Claude writes a new substepIt saves the file into the 06-content folder.
↓
2. Claude has to remember the ruleThe rule lives in a notes file (CLAUDE.md) that says "run content-fixer on new content".
↓
Usually: remembersRuns content-fixer and reports the scores.
Sometimes: forgetsIn a long session the note gets missed. The substep reaches you unchecked.

With a mod

Like a door alarm. It goes off whether anyone remembers or not.

1. Claude writes a new substepIt saves the file into the 06-content folder.
↓
2. The mod notices the saveIt was told to watch for one moment: a new file saved in 06-content.
↓
3. The mod starts content-fixerAutomatically. No memory needed.
↓
4. You get the reportFirst score, final score and what changed. Every time.

So which one should we use?

If the written rule is working, keep it. Both end the same way when things go right.

A mod only adds one thing: it removes the "sometimes forgets" box. It is worth building if you notice substeps reaching you without a content-fixer report.
