Build a Three-Table Join

You'll build one query that pulls facts from three tables — one station at a time. Start with the product list, then add each table and watch a new column appear.

Every table you add is one more JOIN, and it brings one more column. That's all a multi-table join is.
Station 2 · Add the sales numbers
You have the menu Right now your query returns just the product list. To also see how many of each product sold, which table do you JOIN next?
SELECT dp.product_title FROM dim_product dp LEFT JOIN shopify_sales ss ON dp.product_id = ss.product_id
Result columns
product_title net_items_sold
Station 3 · Add the pageviews
You have menu + sales Now to also see how many people looked at each product's page, which table do you add?
SELECT dp.product_title, ss.net_items_sold FROM dim_product dp LEFT JOIN shopify_sales ss ON dp.product_id = ss.product_id LEFT JOIN referrals r ON r.landing_page LIKE '%'||dp.product_slug||'%'
Result columns
product_title net_items_sold pageviews
Read it back
The finished query You just joined three tables: dim_product, shopify_sales, referrals. How many JOIN lines did that take?
SELECT dp.product_title, ss.net_items_sold, r.pageviews FROM dim_product dp LEFT JOIN shopify_sales ss ON dp.product_id = ss.product_id LEFT JOIN referrals r ON r.landing_page LIKE '%'||dp.product_slug||'%'
Reading any multi-table query

Three things that hold it together

Chain, one at a timeStart with one table, add a JOIN for each additional one. Three tables = two JOINs.
One ON per JOINEvery JOIN needs its own ON saying how to match rows — by product_id, or by slug.
AliasesShort names (dp, ss, r) keep a multi-table query readable and tell SQL which table each column came from.
To read one: start at FROM, then take each JOIN in turn — which table, and matched how. One station at a time. Read this way, you can follow a query no matter how many tables it touches.

Build a Three-Table Join (text version)

You build one query across three tables, adding one table per JOIN.

  1. You start with dim_product (the product list). To also see how many of each product sold, you JOIN shopify_sales on product_id. Now each row also shows net_items_sold.
  2. To also see how many people looked at each page, you JOIN referrals, matching the product_slug inside landing_page with LIKE. That match is loose, so on the real data many products show 0 pageviews — that's expected; it gets tightened in Project 3.
  3. Three tables took two JOIN lines: you start from one table and chain a JOIN for each additional one. The short names dp, ss, r are aliases that keep the query readable.

To read a multi-table query, start at FROM, then take each JOIN in turn: which table, and matched how.
