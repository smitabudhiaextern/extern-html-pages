For hundreds, it's impossible to do by hand without missing something.

A compliance analyst checks that a company follows the rules. A vendor is a company that sells supplies to Pfizer. DocuSign is a website for signing documents online, and it stamps the date at the bottom of each page.

Your goal is to extract the right data (dates, vendor names, and document types) while ignoring irrelevant noise.

Two Ideas You'll Use: SDFs and Bounding Boxes

Do you know what SDFs are?

SDFs (Supporting Documentation Files) are basically the official paperwork that comes along with products in the pharmaceutical industry.

Imagine you're Pfizer, and you're buying ingredients from a supplier to make medicine. You can't just trust them blindly. You need documents that prove everything is safe, legit, and follows the rules.

That's what SDFs are. They're a collection of documents like:

  • Quality Certificates: proof that the material is of good quality
  • Compliance Bulletins: proof that the vendor follows industry regulations
  • Chain of Custody forms: a record of who handled the material, when, and where
[Banner image: Pfizer buying an ingredient; supplier hands over Quality Certificate, Compliance Bulletin, Chain of Custody]

Bounding Boxes: The Text, Plus Where It Sits on the Page

Bounding boxes are rectangles that enclose pieces of text, capturing both position and size on a page. This spatial data is essential for understanding how documents are structured.

Positions are coordinates: numbers that say where something is. They're measured in points (1/72 of an inch), and the origin (0, 0) is the top-left of the page, so the numbers grow as you go right and down. Spatial data just means data about where things are.

For example, imagine an SDF where the label "Effective Date:" appears right next to the value "03-Jun-2025." A tool that only extracts text might capture both phrases but lose the connection between them. In contrast, a tool that uses bounding boxes knows that these two pieces of text are next to each other on the page, so it can correctly link the label with the value.

Notice how all recognized text is enclosed within green bounding boxes.

In this project, you'll use PyMuPDF, a Python library that gives you both the text and its position. Go Deeper at the end shows how it compares with other libraries.

A library is a ready-made toolbox of code that someone else wrote, so you don't have to write it yourself.

  2. Extracting Text with Bounding Box Positions When you use .get_text("words"), PyMuPDF extracts each word from the PDF along with its exact position on the page. Instead of just giving a plain text string (like .get_text("text") does), this method provides bounding box coordinates (x0, y0, x1, y1) for each word. 
    # Extract words along with bounding box information
words = page.get_text("words")

# Print first 5 extracted words with bounding boxes
for word in words[:5]:
    print(word)

    words[:5] means "the first five". Each word comes back as a tuple, a fixed group of 8 values. x0, y0 is the top-left corner of the word's box; x1, y1 is the bottom-right. The See page walks through one, value by value.

Words Come Back One at a Time

get_text("words") splits on spaces, so a label like "Date of Manufacture:" comes back as three entries: "Date", "of" and "Manufacture:". Bounding boxes are precise for individual words, but multi-word terms appear fragmented.

Step 4: Extract Text from All Pages

Most PDFs have multiple pages, so we need to extract text from all of them, not just the first one. Instead of manually going page by page, we automate the process using a loop.

  1. Extract the plain text from every page 
    # Loop through all pages and extract text
for page_num in range(len(doc)):
    page = doc[page_num]
    text = page.get_text("text")
    print(f"--- Page {page_num + 1} ---")
    print(text)

    What's Happening Here?

    • len(doc): Finds how many pages are in the PDF.
    • page = doc[page_num]: Gets each page one by one.
    • get_text("text"): Extracts plain text from the page.
    • We print everything neatly, so we can see which text belongs to which page.

    A for loop repeats the same code once for each page: range(len(doc)) gives 0, 1, 2. We add 1 when printing, so you read "Page 1", not "Page 0".

Keep the Page Number

The sample SDF has 3 pages: a Cytiva letter with a product table, a Certificate of Quality, and a Certificate of Quality with a test results table. Keep the page number with every word you extract, so you always know which page it came from.

  1. Keep every word, its page and its box, and save them as JSON This loop does what the callout asks. It reads the words on every page, keeps each word's page, text and box, and saves them all in one file. 
    import json

results = []
for page_num in range(doc.page_count):
    page = doc[page_num]
    for x0, y0, x1, y1, w, *_ in page.get_text("words", sort=True):
        results.append({
            "page": page_num + 1,
            "text": w,
            "bbox": [round(x0), round(y0), round(x1), round(y1)]
        })

with open("sdf_words.json", "w") as f:
    json.dump(results, f, indent=2)

print(len(results))
print([r for r in results if r["page"] == 2 and r["text"].startswith("20")])

    Unpacking gives each value in the tuple its own name in one line, and *_ means "ignore the rest". sort=True puts the words in reading order, top to bottom. A dictionary is labelled values in curly brackets. results is a list (many values in square brackets) of them, and .append() adds one. bbox is short for bounding box. round() rounds to the nearest whole number, so 22.8 becomes 23. JSON is a plain text format other programs can read, and json.dump writes the list into sdf_words.json. The last line keeps only the page-2 entries whose text starts with 20, which is how you spot the two dates.

What Is Metadata?

Metadata in a PDF refers to information about the document, rather than the content inside it. Think of it as a PDF's label. It tells you things like the title, author, subject, keywords, creation and modification dates, and the PDF software used to create it.

Why check metadata? Some PDFs contain valuable document-level information that can be useful for classification.

Extracting Text Block-by-Block (Paragraph-Level)

for block in blocks:

Each block is a tuple of 7 values: the box, the text (\n marks a line break), the block number, and the block type (0 means text).

Pro Tip: Unlike word-level extraction, which gives you fine-grained spatial detail, block-level output is more useful for identifying paragraph structure or large text groupings.
