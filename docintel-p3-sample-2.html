Turn a PDF into Words and Positions with PyMuPDF

Pfizer gets thousands of vendor documents, like quality certificates. A compliance team has to flag any that are more than 3 to 4 years old. Before an AI can do that, a program must read every word and know where it sits on the page, so a date can be matched to its label. Today you build that first layer.

Checked against sample-sdf-document.pdf and the walkthrough video · Oct 28, 2026 · [Content owner], Extern + [Pfizer mentor] · Code tested with PyMuPDF 1.26.5

Python you'll use today (2 min)

Three small bits of Python do most of the work in this step. Here's each one in a sentence and a line or two of code, so nothing in the code below catches you off guard.

A tuple

A fixed group of values in round brackets. You read one by its position, and Python counts from 0, so word[4] is the fifth value: the text.

word = (50.0, 203.2, 71.1, 217.0, 'Date', 8, 0, 0)
word[4]   # 'Date'

A for loop

Does the same thing once for each item, here once for each page. range(doc.page_count) gives 0, 1, 2: one number per page.

for page_num in range(doc.page_count):
    print(page_num)   # 0, then 1, then 2

A list of dictionaries

A dictionary holds labelled values in curly brackets. A list holds many of them in square brackets, and .append() adds one more.

results = []
results.append({"page": 3, "text": "20240315"})

Already know these? Skip to Learn.

Bounding box: the invisible rectangle around a word on the page. It's four numbers: x0 and y0 for the top-left corner, x1 and y1 for the bottom-right corner.

Each number is a coordinate (a position) measured in points, a tiny unit of 1/72 of an inch. In PyMuPDF, (0, 0) is the top-left corner of the page, and y gets bigger as you go down.

Learn: five steps

  1. Install PyMuPDF, a library (ready-made code you can borrow), and import it as fitz.
  2. Open sample-sdf-document.pdf and check it has 3 pages.
  3. Pick page 3 with doc[2] and read its words with get_text("words").
  4. Loop over every page and add each word, sorted top to bottom, to a list of dictionaries.
  5. Save the list as sdf_words.json, a plain text file other tools can read.

The engineer's code for steps 4 and 5

Now the engineer does every page and saves the result. x0, y0, x1, y1, w, *_ gives the first five values their own names in one go, and *_ means "ignore the rest".

results = []
for page_num in range(doc.page_count):
    page = doc[page_num]
    for x0, y0, x1, y1, w, *_ in page.get_text("words", sort=True):
        results.append({
            "page": page_num + 1,
            "text": w,
            "bbox": [round(x0), round(y0), round(x1), round(y1)]
        })

print(len(results))

with open("sdf_words.json", "w") as f:
    json.dump(results, f, indent=2)
617

That's 617 words across the 3 pages, each with its page number and box.

Finding the four page-3 entries

You don't have to scroll through 617 words to find the dates. This loop prints only the four page-3 entries you care about: two labels and two dates.

for r in results:
    if r["page"] == 3 and r["text"] in ("Manufacture:", "20240315", "Expiration", "20260315"):
        print(r)

Where the engineer landed

20240315 is the Date of Manufacture. It has the same top and bottom as "Manufacture:" (203 to 217), so the two sit on the same line, and it starts at x = 200, just to the right of the label.

The label itself comes out as three words, "Date", "of", "Manufacture:", because "words" mode splits on spaces. That's expected. In Step 2 you'll use these positions to join each label to its date.

Every number here comes from running the code above on sample-sdf-document.pdf with PyMuPDF 1.26.5 on Oct 28, 2026. Boxes in sdf_words.json are rounded to whole points.

For this step you only need the first five. Ask Chaitanya to review the plain-English wording for block_no, line_no and word_no.

Why words can come out in the wrong order

PyMuPDF hands you words in the order they're stored inside the file, which isn't always the order you'd read them.

On page 2, without sorting, you get "Certificate of Quality" and then the footer from the bottom of the page (y = 639) before the product details and dates (y = 81 to 166).

Add sort=True and the words come out top to bottom instead:

print([w[4] for w in doc[1].get_text("words", sort=True)][:6])
['Certificate', 'of', 'Quality', 'Product:', 'ÄKTA™', 'ready']

Here w[4] is the word inside each tuple, so this prints just the first six words of page 2, in top-to-bottom order.

f-strings and json.dump

An f-string puts a value inside text. The f before the quotes tells Python to fill in whatever sits in curly brackets.

print(f"Total pages: {doc.page_count}")   # Total pages: 3

JSON is a plain text format for data that almost any tool can read. json.dump writes your list into a JSON file. open("sdf_words.json", "w") opens the file for writing, and indent=2 spreads it over many lines so a person can read it too.

If something breaks

Here are eight errors you might hit in this step. Find the line that looks like what you see, then try the fix.

What you seeWhat it meansFix
ModuleNotFoundError: No module named 'fitz' PyMuPDF isn't installed in this Colab session. Colab forgets installs when the runtime (the computer running your notebook) restarts. Run !pip install pymupdf first, then run the import cell again.
Errors after running pip install fitz "fitz" on pip is a different package that has nothing to do with PDFs. Never install "fitz". Install "pymupdf". You still write import fitz.
FileNotFoundError: no such file: 'sample_sdf.pdf' The name in your code doesn't match the uploaded file, or the file is gone. Check the Files panel on the left. Names must match exactly: "sample-sdf-document.pdf". Drive downloads sometimes add " (1)". After a runtime restart, upload the file again.
ValueError: too many values to unpack (expected 3) Each word is a tuple of 8 values, and you gave names to fewer. Name all 8, or name the first five and ignore the rest: x0, y0, x1, y1, w, *_ = word
get_text returns an empty string "" The page is a scanned picture with no text layer. Try to select text in the PDF. If you can't, it needs OCR, which comes in Project 4.
Words come out in a strange order (the footer before the dates on page 2) PyMuPDF follows the order text is stored in the file, not the order you read it. Use page.get_text("words", sort=True)
"Date of Manufacture:" comes out as three items "words" mode splits text wherever there's a space. Nothing to fix. In Step 2 you'll use regex (a way to search text for patterns) and anchor phrases (fixed labels like "Date of Manufacture:" that tell you where a value is) to join labels and values.
doc.metadata shows '' for title, author and dates (metadata means facts about the file itself) This file has no stored title, author or dates. That's normal and doesn't mean anything failed. Move on.
