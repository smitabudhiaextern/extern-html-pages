How an Engineer Finds Every Word on a Page

Pfizer receives thousands of vendor documents, like quality certificates. A compliance team must flag any that are more than 3 to 4 years old. Before any AI can do that, a program has to read each word and know where it sits on the page. Learn the five steps a document AI engineer follows, then watch one do it.

Checked against sample-sdf-document.pdf and the walkthrough video · Oct 28, 2026 · [Content owner], Extern + [Pfizer mentor] · Code tested with PyMuPDF 1.26.5

Bounding box: four numbers that draw an invisible rectangle around one word. x0, y0 is the top-left corner and x1, y1 is the bottom-right corner.

The page's starting point (0, 0) is its top-left corner. x grows as you move right, and y grows as you move down. Each number is a distance in points (1 point is 1/72 of an inch). This file's pages are 612 points wide and 792 tall.

Learn: five steps

  1. Install PyMuPDF, a library (ready-made code) that reads PDFs. You import it as fitz, its old name.
  2. Open sample-sdf-document.pdf and check it has 3 pages.
  3. Pull out every word with its box, using get_text("words", sort=True).
  4. Save each word as a small labelled record in sdf_words.json. JSON is a plain-text file format that almost any tool can read.
  5. Find a date and check its label sits on the same line.

The engineer's worked example

Here's the code the engineer ran. It installs PyMuPDF with pip (Python's tool for installing libraries), opens the file, then reads all three pages and saves every word with its box.

!pip install pymupdf
import fitz  # PyMuPDF's import name is fitz, its old name
import json

doc = fitz.open("sample-sdf-document.pdf")
print(f"Total pages: {doc.page_count}")      # Total pages: 3

results = []
for page_num in range(doc.page_count):
    page = doc[page_num]
    for x0, y0, x1, y1, w, *_ in page.get_text("words", sort=True):
        results.append({
            "page": page_num + 1,
            "text": w,
            "bbox": [round(x0), round(y0), round(x1), round(y1)]
        })

print(len(results))                            # 617

with open("sdf_words.json", "w") as f:
    json.dump(results, f, indent=2)

How to read an error message (1 min)

Engineers read error messages all day, and you will too. Here's a real one you might see in Colab (Google's free tool for running Python in your browser), and how to read it.

1FileNotFoundError: 2no such file: 'sample_sdf.pdf'

1The error type tells you the kind of problem. FileNotFoundError means Python could not find a file.

2The message tells you what Python was looking for: a file called sample_sdf.pdf.

3So the fix is to compare that name with the Files panel (the folder icon on the left in Colab). The real file is sample-sdf-document.pdf, so change the name in your code to match.

Tuple

A tuple is a fixed group of values inside round brackets. PyMuPDF gives you each word as a tuple of 8 values. Here's the first word it found on page 3:

(480.0, 22.799999237060547, 524.447998046875, 44.784000396728516, 'Cytiva', 0, 0, 0)

The 8 values, in order, are x0, y0, x1, y1 (the bounding box), the word itself, then block_no, line_no and word_no (which chunk of text, which line and which word it is).

You read one item by its position, counting from 0. So word[4] is the text, 'Cytiva'.

Unpacking with *_

Unpacking gives each value in a tuple its own name, in one line.

words = doc[2].get_text("words")   # page 3
x0, y0, x1, y1, w, *_ = words[0]

Now w is 'Cytiva', x0 is 480.0 and y0 is about 22.8.

*_ means "and ignore the rest". Without it, you must name all 8 values. Give fewer names and Python stops with a ValueError.

Loop over pages

A for loop repeats the same code once for each item. range(doc.page_count) gives the numbers 0, 1, 2: one per page.

for page_num in range(doc.page_count):
    page = doc[page_num]
    print(f"Page {page_num + 1}")

Python counts from 0, so doc[0] is page 1 and doc[2] is page 3. That's why the code adds 1 when it prints, so this shows Page 1, Page 2 and Page 3.

The f before the quotes makes an f-string: anything in curly brackets { } gets swapped for its value.

List of dictionaries and JSON

A dictionary holds labelled values in curly brackets. Each label (like "page") points to a value (like 3). Here's one real record from page 3:

{"page": 3, "text": "20240315", "bbox": [200, 203, 244, 217]}

A list holds many items in square brackets, in order. results.append(...) adds one more item to the end. A list of dictionaries is many of these records in one list.

JSON is a plain-text file format that almost any tool can read. json.dump(results, f, indent=2) saves your whole list into sdf_words.json, so the next step of Project 3 can pick it up.
