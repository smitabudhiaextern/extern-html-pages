Spot the Lie — the verification reflex (text version)

This is a self-contained, hypothetical worked example using illustrative sample numbers. It demonstrates the method only. You will run the real verification on your own data.

The number

Suppose Claude tells you the game Dwellings of Eldervale pulled 2,184,000 pageviews to its landing page driving its sales. It looks like a real, plausible number. Is it right or wrong?

Predict

Commit before continuing: does it look right, or is something off? The honest answer is that it is wildly inflated.

The grain trap

The referrals (traffic) table lists the same landing page once per traffic source: Facebook, Google, Instagram, newsletter, and direct each get their own row for the SAME page. If you join products to referrals and SUM pageviews without first aggregating to one row per page, that page's traffic is added once per source — counted over and over. One page times dozens of sources equals a massively inflated total that still looks plausible.

Verify the right way

Fix it in one move: first GROUP BY page to fold each page's sources into a single SUM(pageviews), then join that one-row-per-page result to the product. Suppose the corrected figure lands around 38,200 — the same shape of number without the double-count. These are illustrative numbers; run it on your own table to get your real figure.

The reflex

  • Hand-count a subset: add a few rows yourself and compare to Claude.
  • Cross-check a second way: reach the same number by a different aggregation path.
  • Check the grain: is each event counted exactly once, or does a join repeat rows before the SUM?

Never trust an aggregate you can't check a second way.
