You'll be prompting Claude a lot from here on. A few habits decide whether its answers stay sharp or slowly go wrong, and they all come down to one thing: knowing when to stop adding to a chat and start a new one.

The thing to understand first

Claude re-reads your whole chat every single time

A context window is Claude's working memory for one conversation. Everything in the chat sits inside it: your messages, Claude's replies, and anything you paste. It's measured in tokens, where one token is roughly three-quarters of a word.

Here's the part that matters. Every time you send a message, Claude reads the entire conversation again to answer it. A short chat means a little re-reading. A 60-message chat means it re-reads all 60. Same question, far more tokens spent.

Two consequences. You burn through your usage limit faster as a chat grows, because each new message costs more than the last. And once the window gets full, instructions you gave early can get pushed out and forgotten.
The quiet failure. Old context doesn't just cost tokens, it misleads. Ask for a bot-detection query in the same chat where you did marketing work, and Claude may reach for dim_referrer because it's still sitting there in the conversation.

The rule

When to start a new chat

You're moving to a new Project. Always start a new chat. Nothing from the last Project's data or decisions should follow you in.

You're switching to a different question inside the same Project. Going from marketing analysis to bot detection is a new chat, not a new paragraph.

You realize the setup was wrong 20 messages back. Restarting with a clean brief is faster than untangling it in place.

You want a genuine second opinion. A fresh chat has no earlier answer of its own to defend.

You catch yourself typing "ignore what we did before." That sentence is the signal. If you need it, you needed a new chat.

How to open a new chat

Give Claude everything it needs, and nothing else

A new chat knows nothing, which is the point. Fill in this template so it starts with the facts instead of guessing.

Fresh-chat template 
My data:
  Table: [table name]
  Columns I need: [list the columns, with what each one holds]
My task:
  [one or two sentences on what you're trying to find out]
Already decided, please don't reopen:
  [any choice you've already made]
What I want back:
  [a SQL query / an explanation / a list]
Fill every bracket before you send it. If you can't fill one in, that's the part of the problem you haven't thought through yet, and Claude can't think it through for you.
