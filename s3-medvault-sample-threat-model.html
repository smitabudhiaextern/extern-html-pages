Security Threat Model

MedVault Patient Monitoring System

Client: Riverside General Hospital Prepared by: Security Analyst (Sample) Classification: Confidential
1

Executive Summary

Riverside General Hospital relies on MedVault patient monitoring devices to track vital signs for patients across the ICU and general wards. These 50 devices continuously send heart rate, blood pressure, and oxygen level data to nurses' stations and physician dashboards. When a patient's vitals fall outside safe ranges, the system triggers immediate alerts.

This threat model identifies security risks that could affect patient safety, data privacy, and hospital operations. IoT medical devices are increasingly targeted by attackers: the 2023 healthcare sector saw a 45% increase in ransomware attacks, with IoT devices serving as common entry points.

Our analysis identified three critical concerns requiring immediate attention:

1Weak authentication on the clinical dashboard could allow unauthorized access to patient data and alert settings. Critical
2Unencrypted device communications could be intercepted or modified, causing false readings or missed alerts. Critical
3The central monitoring server is a single point of failure, if compromised, all 50 devices lose connectivity at once. Critical

We recommend prioritizing multi-factor authentication, encrypted communications, and server redundancy.

2

System Overview

Riverside General's MedVault deployment:

  • 300-bed hospital (MedVault customer)
  • 50 MedVault patient monitoring devices (ICU and general wards)
  • Cloud-based data storage and analytics
  • Clinical dashboard for nurses and physicians
  • Real-time vital alerts with escalation protocols
  • Integration with Electronic Health Records (EHR)

Devices measure vitals every 5 seconds → transmit over hospital WiFi to the gateway → gateway forwards to the cloud → cloud checks thresholds and triggers alerts → dashboard shows live vitals and pushes critical alerts to nurses' mobile devices.

Risk Summary

All findings, sorted by priority, for the reader who won't read the full grid.

Critical

  1. Unencrypted device communications (Info Disclosure), vitals sent over hospital WiFi with no encryption; any attacker on the network can capture them.
  2. Weak dashboard authentication (Spoofing), a single password guards all patient data and alert settings; one stolen credential means full access.
  3. Alert system flooding (DoS), no rate limiting, so false alerts can bury real critical ones.
  4. Dashboard tampering (Tampering), users can raise alert thresholds so critical alerts never trigger.
  5. Cloud single point of failure (DoS), all 50 devices depend on the cloud; an outage hits the whole hospital at once.

High

  1. Device network pivot (Elevation), a compromised device becomes an entry point to the hospital network.
  2. Patient data export (Info Disclosure), bulk export allowed with no extra authorization.
  3. Firmware tampering (Tampering), physical access allows firmware changes with no integrity check.
  4. Alert delivery gaps (Repudiation), no confirmation that critical alerts reached their recipient.

Medium

  1. Device spoofing on the network
  2. Dashboard action audit gaps
  3. Alert interception
  4. False alert injection

Recommended Mitigations

For each Critical and High risk, a defense and how hard it is to put in place.

For Critical Risks

RiskProposed mitigationComplexity
Weak dashboard authenticationEnable multi-factor authentication for all clinical dashboard users.Low
Unencrypted device communicationsImplement TLS encryption for all device-to-gateway communication.Medium
Alert system floodingAdd rate limiting and anomaly detection for alert generation.Medium
Dashboard tamperingRequire admin approval for threshold changes; add confirmation dialogs.Low
Cloud single point of failureAdd a local gateway fallback mode with on-premise data caching.High

For High Risks

RiskProposed mitigationComplexity
Device network pivotSegment MedVault devices on an isolated VLAN, separate from the hospital network.Medium
Patient data exportRequire re-authentication for bulk data exports.Low
Firmware tamperingEnable secure boot and signed firmware verification.High
Alert delivery gapsAdd delivery receipts and escalation for unacknowledged critical alerts.Medium
