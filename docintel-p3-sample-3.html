How an Engineer Pulls Every Word and Its Position from a PDF

Pfizer gets thousands of vendor documents called SDFs (Supporting Documentation Files), like quality certificates. A compliance team must flag any that are more than 3 to 4 years old. Before an AI can check a date, a program has to read each word and know where it sits on the page. That is how "20240315" gets matched to "Date of Manufacture:". You'll build that first layer here, in ten small steps, on the real file.

Checked against sample-sdf-document.pdf and the walkthrough video · Oct 28, 2026 · [Content owner], Extern + [Pfizer mentor] · Code tested with PyMuPDF 1.26.5

Bounding box: the invisible rectangle around one word, written as four numbers (x0, y0, x1, y1). These numbers are coordinates: x says how far from the left edge, y says how far from the top.

The starting point (0, 0) is the top-left corner of the page. x grows to the right, and y grows downward.

    Python basics

    Counting from 0: Python numbers things starting at 0. So doc[0] is page 1 and doc[2] is page 3.

    Tuple: a fixed group of values in round brackets. Each line above is one tuple, holding one word. You read an item by its position: word[4] is the text.

    for loop: repeats the same code for each item. words[:3] means "the first three". So this prints three words, one per line.

    Each tuple has eight values. Here's what they mean.

    PositionNameWhat it is
    0 to 3x0, y0, x1, y1The bounding box: left, top, right, bottom
    4wordThe text itself, like 'Cytiva'
    5block_noWhich block (chunk of text) it belongs to
    6line_noWhich line inside that block
    7word_noWhich word inside that line
    You're on track if: you see three lines, and the first one has 'Cytiva' in it. Its x0 is 480, far to the right: that's the company name, Cytiva, in the top-right corner.
    If nothing prints, because words is an empty list []: the page is a scanned picture with no text layer. A text layer is hidden, selectable text stored inside the PDF. This file does have a text layer, so check you opened the right file.

  8. Unpack one word into names.

    Numbers like word[4] are hard to read. Unpacking gives each value a name, so your code says what it means.

    x0, y0, x1, y1, w, block_no, line_no, word_no = words[0]
print(w, x0, y0)
    Cytiva 480.0 22.799999237060547
    Python basics

    Unpacking: giving each value in a tuple its own name, in one line. The left side needs one name for every value. A shortcut: x0, y0, x1, y1, w, *_ = word. The *_ means "and ignore the rest".

    You're on track if: it prints Cytiva 480.0 22.799999237060547. That long number is just how computers store 22.8.
    If you see ValueError: too many values to unpack (expected 3): each word has 8 values and you gave fewer names. Name all 8, or name the first five and end with *_.

  9. Loop over all pages and build a list of dictionaries.

    Now do every page at once, and keep only what we need: page, text and bbox (short for bounding box). sort=True makes the words come out top to bottom, the way you read.

    results = []
for page_num in range(doc.page_count):
    page = doc[page_num]
    for x0, y0, x1, y1, w, *_ in page.get_text("words", sort=True):
        results.append({
            "page": page_num + 1,
            "text": w,
            "bbox": [round(x0), round(y0), round(x1), round(y1)]
        })

print(len(results))
print(results[0])
    617
{'page': 1, 'text': 'Cytiva', 'bbox': [547, 88, 576, 98]}
    Python basics

    range(doc.page_count): gives the numbers 0, 1, 2, one per page. The loop runs the same code for each page. We add 1 so the saved page number reads 1, 2, 3 like a person would count.

    Dictionary: labelled values in curly brackets, like {"page": 3, "text": "20240315", "bbox": [200, 203, 244, 217]}.

    List: many values in square brackets. results starts empty, [], and .append() adds one dictionary at a time. len(results) counts them.

    You're on track if: it prints 617, the number of words in the whole file.
    If the words come out in a strange order (on page 2, the footer shows up before the dates): you left out sort=True. PyMuPDF follows the order the text is stored in the file, not the order you read it.

  10. Save it as sdf_words.json.

    Last step: save your list to a file, so the next lesson (Project 3, Step 2: pulling out the fields) can read it.

    with open("sdf_words.json", "w") as f:
    json.dump(results, f, indent=2)
    Python basics

    JSON: a plain-text format for saving data, made of lists and dictionaries. Almost every program can read it.

    json.dump: writes your list into the file. indent=2 spreads it over lines so a person can read it too.

    You're on track if: sdf_words.json appears in the Files panel. Double-click it and search for 20240315. You'll find it with page 3 and the box 200, 203, 244, 217.

get_text("blocks"): paragraphs instead of words

Words mode gives you one item per word. Blocks mode gives you one item per chunk of text, closer to a paragraph. Here's what the engineer got for the first block on page 3.

blocks = doc[2].get_text("blocks")
print(len(blocks))
print(blocks[0])
26
(480.0, 22.799999237060547, 524.447998046875, 44.784000396728516, 'Cytiva\n', 0, 0)

Each block has seven values: the four box numbers, the text, the block number, and the block type (0 means text, 1 means image). The \n is a line break. Blocks are handy when a label and its value sit in the same chunk.

Why sort=True matters on page 2

PDFs store text in whatever order the file was made, not the order you read. Here are the first words of page 2 without sorting:

'Certificate', 'of', 'Quality', 'This', 'product', 'is', 'manufactured', 'in', 'compliance', 'with'

"This product is manufactured..." is the footer, near the bottom of the page (y = 639). It jumps ahead of the product details and dates, which sit near the top (y = 81 to 166). With sort=True, the words come out top to bottom:

'Certificate', 'of', 'Quality', 'Product:', 'ÄKTA™', 'ready'

If you later look for "the word after the label", the wrong order can pair a label with the wrong value. Sorting first avoids that.

Searchable PDFs vs scanned PDFs

A searchable PDF has a text layer: hidden text stored inside the file, which PyMuPDF can read. A scanned PDF is just a photo of paper. PyMuPDF finds no words in it, so get_text("words") gives back an empty list.

Quick test: open the PDF and try to highlight a word with your mouse. If you can, it's searchable. sample-sdf-document.pdf is searchable. Many real vendor documents are scans, and Project 4 handles them with OCR (software that reads text from images).
