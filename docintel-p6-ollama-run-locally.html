Before you start

There are three things we want you to know before you decide to do this.

There is an easier option

Groq is an online service that runs open-source models for you. It needs no GPU and no setup on your computer.

Find it in Project 8, on the page "Full RAG Pipeline with Gradio UI", in the box "No GPU? Use a free hosted open-source model."

Small models make more mistakes

An AI model is the program that reads your question and writes an answer. The ones here are small enough to fit on a laptop, so they make more mistakes than big ones like Gemini.

Externs reported about 65% correct answers with Phi-2 and about 30% with TinyLlama. The host company needs answers that are close to perfect, so think of this as a way to learn.

Ollama inside Colab does not help

You may see guides that run Ollama inside Colab. That still uses Colab's GPU limits, so this guide runs the model on your own computer instead.

What you need

The model has to fit in your RAM while it works. RAM is your computer's short-term memory, the space it uses for whatever is running right now. So the amount of RAM you have decides which model you can use.

1. Check your RAM and system version

Both numbers are in the same About window.

  • On a Mac: click the Apple menu, choose About This Mac. Read the number next to "Memory". The same window shows your macOS version.
  • On Windows: open Settings, then System, then About. Read the number next to "Installed RAM". The system version is the number next to "Version".

2. Make sure your computer runs one of these

  • macOS 14 (Sonoma) or newer
  • Windows 10 version 22H2 or newer (Windows 11 counts)
  • Linux

You also need about 15 GB of free disk space. That covers Python, VS Code, Ollama, your model and the packages the notebook installs.

3. Pick your model

Each model has a short name called a tag. You type the tag to download and use that model. Pick the amount of RAM you found, and we are going to show you the model we think fits your computer.

Suggested models

Step 1Install Ollama

In this step you are going to install Ollama, the free app that downloads open-source AI models and runs them on your own computer. It is how your notebook will talk to a local model instead of one in the cloud.

The download page leads with a command to type, but the steps below use the normal installer instead.

On a Mac

  1. Go to ollama.com/download and pick the macOS tab.
  2. Click "Download manually". You get a file called Ollama.dmg.
  3. Open Ollama.dmg and drag Ollama into your Applications folder.
  4. Open Ollama from your Applications folder. If macOS warns that it was downloaded from the internet, click Open.
  5. If Ollama asks to install its command line tool, allow it and enter your Mac password. The command line tool is the small program that lets you type ollama commands in Terminal.

On Windows

  1. Go to ollama.com/download and pick the Windows tab.
  2. Click "Download manually". You get a file called OllamaSetup.exe, which is about 1.7 GB.
  3. Double-click OllamaSetup.exe and follow the installer. You do not need to be an administrator.

On Linux: follow the instructions on ollama.com/download.

When it is done: if a chat window opens, you can close it. Ollama keeps running in the background.

Step 2Download a model and test it

In this step you are going to download a model and ask it one question, before you touch any Python. If this works, you know Ollama is set up correctly.

You will use the terminal, a window where you type commands to your computer instead of clicking.

Open the terminal on a Mac

Press Command and Space, type Terminal and press Enter.

Open the terminal on Windows

Click Start, type PowerShell and press Enter.

  1. Type this and press Enter to download the model. If you picked a different model from the table, type its tag instead of phi.
    Command
    ollama pull phi
  2. Wait for the download to finish. It ends with the word "success".
  3. Type this and press Enter to start a chat with the model. Again, use your own tag if you picked a different model.
    Command
    ollama run phi
  4. Type a question, such as "What is Retrieval-Augmented Generation?", and press Enter. The model writes its answer in the terminal.
  5. When you are done, type this and press Enter to leave the chat.
    Command
    /bye

You know it worked when you got an answer. That means Ollama and your model are working. If you saw an error, look at Troubleshooting at the end of this guide.

Why %pip and not !pip?

A package is ready-made code that someone else wrote and shared, and pip is the tool that downloads packages for Python. The new line starts with %pip instead of !pip, because %pip installs packages into the same copy of Python your notebook is using.

DELETEDelete these 7 cells

Delete each cell that starts with one of these lines. They are the cells marked DELETE in the map above.

  • import torch (checks for a Colab GPU)
  • # Check CUDA version first (installs llama-cpp)
  • !pip install llama-index (this cell has only this one line)
  • from llama_cpp import Llama (downloads Mistral and loads it)
  • # Test with a RAG query (tests the model)
  • !pip install pymupdf (installs pymupdf and the llama-cpp connection)
  • !pip install llama-index-embeddings-huggingface (installs the embedding package)
Why can I delete these?

These cells set up Colab's GPU, install llama-cpp (the tool the Colab notebook uses to run Mistral), download and test Mistral, or install packages that Edit 1 already installs. Step 2 already tested your model in the terminal, so you can delete the test cell too.

What you will see while it runs

  • VS Code may ask to install ipykernel, the small package that lets VS Code run Python in a notebook. Click Install.
  • The install cell is slow, mostly because it installs PyTorch, a large tool the embedding model needs. It ends with "Successfully installed...". It may also say you may need to restart the kernel. You do not need to.
  • Red warning lines are fine unless the cell ends in an Error.
  • The first run downloads the embedding model (about 130 MB) and shows progress bars. On Windows it may print a red "symlinks" warning, which is fine.
  • A local model is slower than Gemini, because your laptop does all the work. The first answer can take a minute or more, because Ollama has to load the model into memory first. A Mac with an Apple M-series chip is usually much faster than a laptop without a GPU.

Troubleshooting

If something went wrong, open the message that looks most like what you saw.

You see "connection refused" or "failed to connect"

Ollama is not running. Open the Ollama app, or open a terminal and run this, then run the cell again:

Command
ollama serve

If ollama serve says "address already in use" (on Windows the message says "Only one usage of each socket address"), Ollama is already running, so just run the cell again.

You see a timeout error

The model took longer than the notebook was told to wait. In the Ollama(...) line, raise request_timeout, for example to this, then run the cell again:

Code
request_timeout=600.0
The notebook runs out of memory, or the answer is very slow

The model is too big for your computer's RAM. Close other apps, especially web browsers with many tabs.

If that does not help, switch to a smaller model from the table, such as phi or tinyllama. Remember to run ollama pull for the new tag and to change the tag in the notebook.

You see "model not found"

The full message looks like this:

Message
model "phi" not found, try pulling it first

Ollama does not have a model with that exact tag. Run ollama pull with the exact tag, for example:

Command
ollama pull phi

To see the tags you have downloaded, run this. The tag in your notebook must match one of them exactly.

Command
ollama ls
