What do these words mean?

Google Colab is the website where you have been running notebooks so far. It runs in the cloud, which means computers owned by a company that you reach over the internet.

A GPU is a special chip that makes AI models run fast, and Colab only lends you one for a limited time.

An AI model is the program that reads your question and writes an answer. Ollama is a free app that downloads open-source AI models and runs them on your own computer. When something runs on your own computer, we call it local.

This helps when Colab's free GPU time runs out, or when you want your documents to stay on your own computer so nothing is sent to an outside company.

  • There is an easier option with no setup. Groq is an online service that runs open-source models for you. It is in Project 8, on the page "Full RAG Pipeline with Gradio UI", in the box "No GPU? Use a free hosted open-source model."
  • Small models make more mistakes. Externs got about 65% correct answers with Phi-2 and about 30% with TinyLlama. The host company needs answers that are close to perfect, so use this to learn.
  • Why not run Ollama inside Colab?

    You may also see guides that run Ollama inside Colab, but that still uses Colab's GPU limits, so this guide runs the model on your own computer instead.

What you need

Your RAM decides which model you can use.

What is RAM?

RAM is your computer's short-term memory, the space it uses for whatever is running right now. The model has to fit in your RAM while it works.

Check your RAM and system version

  • On a Mac: click the Apple menu and choose About This Mac. Read the number next to "Memory" and your macOS version.
  • On Windows: open Settings, then System, then About. Read the number next to "Installed RAM" and the number next to "Version".

You need macOS 14 (Sonoma) or newer, Windows 10 version 22H2 or newer (Windows 11 counts) or Linux, plus about 15 GB of free disk space.

Pick your model

Each model has a short name called a tag. The tag is the name you type. Pick the amount of RAM you found, and we are going to show you the model we think fits your computer.

Pick your RAM above to see your model.

Not sure? Start with phi. On an 8 GB Mac, use phi.

Step 1Install Ollama

Done

The download page leads with a command to type, but the steps below use the normal installer instead.

On a Mac

  1. Go to ollama.com/download and pick the macOS tab.
  2. Click "Download manually". You get a file called Ollama.dmg.
  3. Open Ollama.dmg and drag Ollama into your Applications folder.
  4. Open Ollama from your Applications folder. If macOS warns that it was downloaded from the internet, click Open.
  5. If Ollama asks to install its command line tool (the small program that lets you type ollama commands in Terminal), allow it and enter your Mac password.

On Windows

  1. Go to ollama.com/download and pick the Windows tab.
  2. Click "Download manually". You get a file called OllamaSetup.exe, which is about 1.7 GB.
  3. Double-click OllamaSetup.exe and follow the installer. You do not need to be an administrator.

On Linux: follow the instructions on ollama.com/download.

If a chat window opens, you can close it. Ollama keeps running in the background.

You know it worked when you see the llama icon in your menu bar (Mac) or system tray (Windows), or when http://localhost:11434 shows "Ollama is running".

What does this mean?

The menu bar is the row of small icons at the top right of a Mac screen, and the system tray is the row of small icons next to the clock on Windows. "localhost" means "this computer", so that address never leaves your machine.

Step 2Download a model and test it

Done

You will use the terminal, a window where you type commands to your computer instead of clicking. On a Mac, press Command and Space, type Terminal and press Enter. On Windows, click Start, type PowerShell and press Enter.

  1. Type this and press Enter to download the model. If you picked a different model, type its tag instead of phi.

Done
What does this mean?

A notebook is a file where you write and run code in small blocks called cells. A notebook file ends in .ipynb.

A kernel is the copy of Python that runs your notebook's code. Venv makes a fresh, private copy of Python just for this project, so the packages you install here do not mix with anything else on your computer.

Get the notebook

  1. Open the Project 6 notebook "RAG with Open Source models" from the task "Run Your First Open-Source LLM": https://colab.research.google.com/drive/1-cVc_RnF9ZIWds3zINvEGaD8OJOUa6fY. Use this original, not a copy you changed, so the cells match Step 4.
  2. In the menu at the top, click File, then Download, then Download .ipynb.
  3. Make a new folder for this project and move the notebook file into it.

Get the PDF

  1. Open the sample SDF PDF from the Project 6 task: https://drive.google.com/file/d/1oOR50D8F3Deask7aT2HbXQZhw0u1hvcg/view
  2. Click the download icon at the top right. The file downloads as sample-sdf-document.pdf.
  3. Rename the downloaded file to sample_sdf.pdf and move it into the same folder as the notebook.

Watch out: Windows and Mac sometimes hide the .pdf at the end of a file name. If you cannot see .pdf, type only sample_sdf, or you can end up with sample_sdf.pdf.pdf.

Open it in VS Code

  1. Open VS Code. Click File, then Open Folder, and pick your new folder. If VS Code asks "Do you trust the authors?", click Yes.
  2. Look at the file list on the left and check that the PDF's name is exactly sample_sdf.pdf. If it shows sample_sdf.pdf.pdf, right-click it, choose Rename and remove the extra .pdf.
  3. Click the notebook file to open it.
  4. Click "Select Kernel" at the top right of the notebook. Choose Python Environments, then Create Python Environment, then Venv, then Python 3.12.

    If Python 3.12 does not show up in the list, install Python again.

You know it worked when the top right of the notebook shows ".venv (Python 3.12...)".

Why do I need to change it?

The notebook was built for Colab. It sets up Colab's GPU, downloads the Mistral model file itself and reads files from Colab's /content/ folder. On your computer, Ollama handles the model.

The DELETE cells set up Colab's GPU, install llama-cpp (the tool the Colab notebook uses to run Mistral), download and test Mistral, or install packages that Edit 1 already installs. Step 2 already tested your model in the terminal, so you can delete the test cell too.

Everything else stays the same, including the embedding model from HuggingFace (a website where people share AI models). An embedding model is a small model that turns text into numbers so the computer can find matching passages, and this one already runs on your own computer.

Why %pip and not !pip?

A package is ready-made code that someone else wrote and shared, and pip is the tool that downloads packages for Python. The new line starts with %pip instead of !pip, because %pip installs packages into the same copy of Python your notebook is using.

What do these settings mean?

request_timeout=300.0 tells the notebook to wait up to 300 seconds (5 minutes) for an answer before giving up, because local models can be slow. context_window=2048 limits how much text the model reads at once to the same amount the Colab notebook used.

Normal things you may see while it runs
  • VS Code may ask to install ipykernel, the small package that lets VS Code run Python in a notebook. Click Install.
  • The install cell is slow, mostly because it installs PyTorch, a large tool the embedding model needs. It ends with "Successfully installed...". It may also say you may need to restart the kernel. You do not need to.
  • The first run downloads the embedding model (about 130 MB) and shows progress bars. On Windows it may print a red "symlinks" warning, which is fine.
  • A local model is slower than Gemini, because your laptop does all the work. The first answer is slow because Ollama has to load the model into memory first. A Mac with an Apple M-series chip is usually much faster than a laptop without a GPU.

You know it worked when the PDF cell prints a line like "Extracted 350 words from the PDF." and the last cell prints the model's answer in plain words.

Troubleshooting

Open the problem that matches what you see.

You see "connection refused" or "failed to connect"

Ollama is not running. Open the Ollama app, or open a terminal and run this, then run the cell again:

Command
ollama serve

If ollama serve says "address already in use" (on Windows the message says "Only one usage of each socket address"), Ollama is already running, so just run the cell again.

PowerShell says "ollama" is not recognized

PowerShell was open while Ollama was installing, so it has not found Ollama yet. Close PowerShell, open it again, then try the command again.

You see a timeout error

The model took longer than the notebook was told to wait. In the Ollama(...) line, raise request_timeout, for example to this, then run the cell again:

Code
request_timeout=600.0
The notebook runs out of memory, or the answer is very slow

The model is too big for your computer's RAM. Close other apps, especially web browsers with many tabs.

If that does not help, switch to a smaller model, such as phi or tinyllama. Remember to run ollama pull for the new tag and to change the tag in the notebook.

You see "model not found"

The full message looks like this:

Message
model "phi" not found, try pulling it first

Ollama does not have a model with that exact tag. Run ollama pull with the exact tag, for example:

Command
ollama pull phi

To see the tags you have downloaded, run this. The tag in your notebook must match one of them exactly.

Command
ollama ls
